# 视觉目标卡 — vendor-if-doctor（医院厂商接口连通巡检库）

> 本卡用于与 Phase 4 末尾采集的真实截图做对照。配色 / 字体 / 信息层级 / 画面元素均
> 须能由当前依赖（typer + rich + jinja2 + 简单 HTML）落地；**不**承诺 WebGL / 动画
> / 3D 等超出技术栈的范围。
> **三态草图**（终端 ASCII 80×24）见 `docs/concepts/三态草图.md`。

## 一、配色规范（hex，硬约束）

| 用途 | hex | 落地层 | 备注 |
|------|-----|--------|------|
| 背景（终端 / HTML 周报） | `#f8f9fa` | rich `Style(bgcolor=...)` + HTML `<body>` | 近白底，长时间看不刺眼 |
| 主键（标题 / 表头 / 接口 FQN） | `#2c3e50` | rich `Style(color='#2c3e50', bold=True)` + HTML `h1`/`h2` | 深石板蓝 |
| 主键 — 强调（healthy 大字） | `#1c5d99` | rich `Style(bold=True)` + HTML `.rate-headline` | 与背景对比度 ≥ 4.5:1 |
| healthy | `#28a745` | rich `Style(color='#28a745')` + HTML `.status-healthy` | 绿 |
| degraded | `#ffc107` | rich `Style(color='#ffc107')` + HTML `.status-degraded` | 琥珀（部分通过 + warning） |
| failed | `#dc3545` | rich `Style(color='#dc3545')` + HTML `.status-failed` | 红 |
| critical 升级提示 | `#b21f1f` | rich `Style(bold=True, color='#b21f1f')` + HTML `.severity-critical` | 失败告警分级里专用于 critical |
| warning 升级提示 | `#946800` | rich `Style(color='#946800')` + HTML `.severity-warning` | 琥珀加深，比 degraded 更醒目 |
| 凭据占位 / 隐文 | `#6c757d` | rich `Style(dim=True, color='#6c757d')` + HTML `.credential-mask` | 灰色，永远不显示明文 |
| 表格斑马底（终端无） | `#f1f3f5` | HTML `.zebra` | 周报表格偶数行 |

> **强制约束**：上表 7 个 hex（背景 + 主键 + healthy / degraded / failed + critical + 凭据占位）
> 必须出现在所有渲染层（CLI / Markdown / HTML）；终端渲染用 rich 库的
> `Style(color=...)` 落地；HTML 周报用内嵌 `<style>` 块，离线打开即可生效。
> **任何超出此 7 色的配色视为越界，须删除**。

## 二、字体族

| 层 | 字体族 | 字号 / 行高 | 用途 |
|----|--------|-------------|------|
| 终端 / 日志 | `Menlo, Consolas, "DejaVu Sans Mono"` | 12–13px / 1.4 | CLI 输出 + JSON 日志 |
| CLI 帮助 / 配置 | `Tahoma, "Microsoft YaHei", sans-serif` | 14px / 1.5 | typer `--help` + 配置文件示例 |
| HTML 周报 | `system-ui, -apple-system, "PingFang SC", Tahoma, sans-serif` | 14px / 1.6 | 周报内文字 |
| 表格数字 | `Menlo`（终端）/ `system-ui`（HTML） | 12–14px | 百分比 / latency_ms / 计数 |
| 一律不画 emoji 字符作为状态标识 | — | — | 运维读者容易把 ❌ 当真，用文字标签 `healthy / degraded / failed` + 色块双标识 |

> **不引入** Google Fonts / 远程字体 / 自带 woff 文件；周报 HTML 用 system-ui 即可，
> 不依赖外网也能正确显示。

## 三、信息层级（首屏 → 展开 → 详情）

```
┌─────────────────────────────────────────────────────────────┐
│ 首屏（信息密度最高，眼睛第一落点）                           │
│   L1 健康率大字： 75% （≥ 48px，#1c5d99 加粗）              │
│   L2 跑批计数  ：8 / 8 vendor 已跑  （16px，#2c3e50）        │
│   L3 三态小计  ：healthy 6 | degraded 1 | failed 1          │
│         └ healthy #28a745 / degraded #ffc107 / failed #dc3545│
├─────────────────────────────────────────────────────────────┤
│ 表格层（次落点，按 vendor 分组）                             │
│   T1 列表头：vendor_id | interface_id | status | first_step │
│   T2 行：每行 1 个 vendor.interface，按 status 排序         │
│         （failed 置顶 → degraded → healthy，severity 同档） │
│   T3 行尾：evidence_hash 前 8 位小灰字                       │
├─────────────────────────────────────────────────────────────┤
│ 详情层（点 vendor 行 / `--detail` 展开）                    │
│   D1 step 名：preflight / auth / list / sample / assert      │
│   D2 latency_ms：≤ 1500 ms 视为合格（粗体数字）             │
│   D3 summary：1 句话描述，失败原因含 failure_class 标签      │
│   D4 Evidence.command：可复制执行的排查命令                  │
│   D5 suggested_actions：1–3 条具体排查动作                    │
├─────────────────────────────────────────────────────────────┤
│ 工单层（仅 failed / degraded 才有）                          │
│   W1 tickets.jsonl 每条 1 行 JSON                           │
│   W2 字段：vendor_id / interface_id / first_failed_step /   │
│          severity / priority / suggested_actions[]          │
│   W3 凭据一律 '***'，值班员人审后粘入工单系统               │
└─────────────────────────────────────────────────────────────┘
```

**层级纪律**：

- L1 / L2 字号 ≤ L1 字号 × 0.6；不出现「首屏两个大字」（视觉冲突）
- T1 表头比 T2 数据行字号大 1–2px 或加粗
- D 详情块在 L / T 之后，**不允许**在首屏直接出现
- W 工单层只有 failed / degraded 才出现；healthy 不进工单

## 四、三态精确到字段（每态指出「屏幕上能看到哪些字段」）

### 起始态（命令行没有跑出来之前）

**屏幕画面**：终端 80 × 24，ASCII 字符滚动一行。

**可见字段**：
- 命令行：`$ vendor-if-doctor run --vendor all --config production.yaml`
- 进度条（rich `Progress`）：`[▌▌▌▌▌   ] running his.outpatient-register …  (latency 312ms)`
- 颜色：进度条主色 `#2c3e50`，文字 `#f8f9fa` 底
- 任何 vendor 名字完整可见；不展开细节；不打印响应体
- 不出现 `handover.md` / `tickets.jsonl` / `vendor_if_doctor.db` 路径（跑出来才知道）

### 首个可用瞬间（一次 run 完成）

**屏幕画面**：终端打印汇总 + 同目录生成三件套。

**终端可见字段（每个字段都有 hex 与字号对应）**：

```
$ vendor-if-doctor run --vendor all @ 2026-10-10 08:30    ← #2c3e50 主键，14px
================================================================
vendor_count    : 8                                          ← #2c3e50 主键
healthy         : 6                                          ← #28a745 healthy
degraded        : 1                                          ← #ffc107 degraded
failed          : 1                                          ← #dc3545 failed
health_rate     : 75.0%                                      ← #1c5d99 大字（≥ 48px 在 HTML；终端粗体）
handover_md     : ./out/2026-10-10/handover.md  (768 B)      ← #2c3e50 主键
tickets_jsonl   : ./out/2026-10-10/tickets.jsonl  (2 lines)  ← #2c3e50 主键
sqlite_history  : ./out/vendor_if_doctor.db  (8 rows, WAL)   ← #2c3e50 主键
================================================================
OK                                                              ← #28a745 healthy
```

**同目录三件套**（真实相对路径）：
- `out/2026-10-10/handover.md`：每 vendor 段 H2 / 每接口 H3 + 色块状态（healthy `#28a745` / degraded `#ffc107` / failed `#dc3545`）+ first_failed_step
- `out/2026-10-10/tickets.jsonl`：仅 failed / degraded，每行 JSON 含 `severity` + `priority` + `suggested_actions[]` + `first_failed_step`
- `out/vendor_if_doctor.db`（WAL 模式）：`inspection_runs_y2026m10` 月表 8 行 + 3 索引（`idx_run_id_y2026m10` / `idx_vendor_id_y2026m10` / `idx_started_at_y2026m10`）

### 成形态（连跑一周 + 周报呈现）

**屏幕画面**：单文件 HTML 离线可看，三栏布局（无外部资源）。

**HTML 周报三栏**（每栏必须含的字段）：

| 栏 | class | 字段 | 备注 |
|----|-------|------|------|
| 连通率柱状条 | `.system-rate` | 业务系统（如 `his` / `lis` / `pacs` / `emr` / `medical-insurance`）+ 健康率百分比 + 8 格柱状条（`████████░░ 88%`）+ 三态色块 | 按连通率 asc 排序，最差置顶 |
| 7 天趋势 | `.trend-spark` | 过去 7 天每日一根 7 字符 ASCII 火花（`▁▂▃▄▅▆▇█`）+ 当日 win / loss 颜色 + 总数 | 颜色按 win/loss 自动切换 |
| 异常清单 | `.anomaly-list` | 每行 `vendor.interface` \| `status` \| `first_failed_step` \| `evidence_hash(8)` \| `suggested_actions` | 仅今日失败 + warning |

**HTML 周报颜色纪律**：
- `.system-rate` 行底色按 healthy `#28a745` / degraded `#ffc107` / failed `#dc3545` 切换
- `.trend-spark` 字符色按当日 win（#28a745）/ loss（#dc3545）/ mixed（#ffc107）
- `.anomaly-list` 表头加粗 `#2c3e50`，表行斑马底 `#f1f3f5`

**HTML 周报字体纪律**：
- `<h1>` 用 `system-ui` 18px / `#1c5d99`
- `<table>` 用 `system-ui` 14px / 行高 1.6
- 数字列用 `Menlo` 14px / 等宽对齐

## 五、画面类型约定（与本轮交付形态一致）

* **`event-daemon` / 常驻**：默认 **不**驻守；本轮以「**单次 CLI 跑批**」为主，常驻由用户
  的 cron / Windows 计划任务拉起。CLI、Markdown 周报、JSONL 工单草稿、SQLite 历史四件套是
  主要触达面。
* **终端会话**：typer + rich 输出 80×24 滚动 ASCII。
* **HTML 周报**：单文件离线可看，三栏布局。
* **Markdown 值班清单**：jinja2 模板输出，肉眼半小时内能扫完。
* **JSONL 工单草稿**：值班员人审后粘入工单系统。

> 不画 web 大屏 / 3D 动画 / 实时图表。一切只做能在终端 + 静态 HTML 里看清。

## 六、不画的东西（强制约束）

* **不**画 WebGL / D3 动态图：用纯 ASCII 火花图代替
* **不**画实时折线动画：周报里只用 **静态** ASCII 火花图（横向 7 列）
* **不**画诊所化 UI（图标 + 卡片）：用一行 ASCII 表格代替
* **不**画 emoji 当作状态：色块 + 文字双标识
* **不**画过宽画布：所有画布约束在终端 80×24、单 HTML 页宽度 ≤ 1024px

## 七、可被 Phase 4 末尾实测采证的元素（grep 锚点）

实测命令（Phase 4 收尾时由值班员人工运行）：

```bash

cat out/demo/handover.md

```

期望产物（写进 README「## 输出样例」与「## 概念 / 实测对照」）：

* `handover.md` 含 `Status: healthy` / `Status: degraded` / `Status: failed` 三色行
* `tickets.jsonl` 含至少 1 条 `first_failed_step` + `suggested_actions`

* `weekly.html` 含 `.system-rate` × 6（his/lis/pacs/emr/medical-insurance/regional）+ `.trend-spark` × 7（7 天）+ `.anomaly-list` × 1 三块
